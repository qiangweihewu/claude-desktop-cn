# Claude Desktop CN v1.6.38

紧急修复版：上一版（v1.6.37）和 v1.6.36 在 macOS 上发完消息后引擎会立刻报 `Cannot find package 'bundle'` 然后无法继续，本版彻底解决。

## 主要更新

### 1. 修复 macOS 安装版引擎启动崩溃 (`Cannot find package 'bundle'`)

**问题**：从 v1.6.x 起 upstream Claude Code 引擎源码里加了 `import { feature } from 'bun:bundle'`，但 `bun:bundle` 是 `bun build` 的**编译期专用虚拟模块**，运行时根本不存在。本项目把引擎当作 `.ts` 源文件直接打包并通过 `bun ./cli.tsx` 运行，所以每次发消息都会立刻被这条 import 卡住。

**修复**：在 `engine/preload.ts` 里注册 Bun 运行时插件，把 `bun:bundle` 拦截到一个本地 stub，提供 `feature(name)` 函数。所有 upstream feature flag（`KAIROS`、`COORDINATOR_MODE`、`BRIDGE_MODE` 等共 90+ 个，都是 upstream 的可选/实验功能）默认返回 `false`，不影响桌面端的对话主路径。

**留出口子**：未来如果发现某个 flag 是必需的，只需在 `preload.ts` 的 `ENABLED_FEATURES` 里加名字即可，不用改 upstream 源码。

### 2. 验证

本地通过：

```bash
cd engine
bun --preload ./preload.ts ./src/entrypoints/cli.tsx --version
# → 999.0.0-local (Claude Code)

bun --preload ./preload.ts ./src/entrypoints/cli.tsx --help
# → 完整命令帮助输出，无错误

# 实际 stream-json 调用：引擎正常进入 SessionStart 周期
echo '{"type":"user",...}' | bun --preload ... cli.tsx --print --input-format stream-json --model claude-sonnet-4-6
```

## 升级建议

**强烈建议** macOS 用户升级到 v1.6.38。v1.6.36 / v1.6.37 上对话发不出去就是这个 bug。
