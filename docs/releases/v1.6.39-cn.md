# Claude Desktop CN v1.6.39

继续修 v1.6.38 没修干净的引擎崩溃问题。

## 主要更新

### 1. CI 里的 Bun 版本从 1.2.23 升到 1.3.11

v1.6.38 在 `engine/preload.ts` 里加了 `bun:bundle` 运行时 shim。本地 bun 1.3.11 上验证通过，但**安装包里的 bun 是 1.2.23**，1.2.23 把 `bun:*` 命名空间在 plugin 之前就短路了，所以 shim 不生效，用户依然看到 `Cannot find package 'bundle'`。

修复：把 GitHub Actions workflow 里的 `oven-sh/setup-bun@v2 bun-version` 从 `1.2.23` 改到 `1.3.11`，让 CI 把新版 bun 二进制打进 macOS / Windows 安装包。

### 2. 验证

直接用安装包里的 bun 复现：

```bash
# bun 1.2.23（v1.6.38 安装包里那个）→ 失败
$ /Applications/Claude\ Desktop\ CN.app/.../bin/bun --preload preload.ts cli.tsx --version
error: Cannot find package 'bundle' from '.../cli.tsx'

# bun 1.3.11（v1.6.39 起将打入安装包）→ 成功
$ /Users/zachlai/.bun/bin/bun --preload preload.ts cli.tsx --version
999.0.0-local (Claude Code)
```

完整 stream-json 流程跑通：引擎正常进入 SessionStart 周期，无模块错误。

## 升级建议

**所有 macOS 用户必须升级到 v1.6.39**。v1.6.36 / v1.6.37 / v1.6.38 在 macOS 上发消息都会报 `Cannot find package 'bundle'`。
