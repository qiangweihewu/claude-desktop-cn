# Claude Desktop CN v1.6.40

新增**本机联网搜索**能力，不再依赖上游 API 或中转站是否支持 `web_search_20250305`。

## 主要更新

### 1. 设置页新增「联网搜索」section

设置侧边栏在「API 配置」之后增加「联网搜索」入口，提供四个选项：

| Provider | 配置 | 适用场景 |
|---|---|---|
| 不启用 | — | 保持现状，由上游 API 决定 |
| **DuckDuckGo** | 零配置、免费 | 默认推荐，日常查询足够 |
| Tavily | 注册 tavily.com 拿 Key | 质量最高，1000 次/月免费 |
| Brave Search | 申请 Brave Search API Key | 备选，2000 次/月免费 |

设置内置「测试一下」按钮，填查询即可看本地搜索是否能拿到结果，省得每次跑完整对话调试。

### 2. bridge-server 增加本地搜索拦截

`electron/bridge-server.cjs` 新增三个搜索后端 + 一个拦截器：

- `searchViaDDGLite(query)`：纯 fetch + 正则解析 DDG Lite 的 HTML，零外部依赖
- `searchViaTavily(query, apiKey)`：调 Tavily 的 `/search` API
- `searchViaBrave(query, apiKey)`：调 Brave Search 的 web search API
- `handleLocalWebSearchProxy()`：拦截后合成符合 Anthropic 标准的 `server_tool_use` + `web_search_tool_result` + 文本总结 SSE 响应

拦截优先级调整为：

```
用户配置了本地 backend → 用本地 backend，所有上游格式通吃
否则 OpenAI provider 支持 DashScope/BigModel → 走原有 native search
否则 OpenAI provider 不支持 → strip 工具
否则 Anthropic 格式 → 透传给上游
```

### 3. 持久化 + REST 端点

配置保存在 `userData/web-search-config.json`。三个新 endpoint：

- `GET /api/web-search/config` — 返回 provider + 各 API key 是否已配置（key 本身从不返回）
- `POST /api/web-search/config` — 保存（API key 留空表示不修改）
- `POST /api/web-search/test` — 用当前配置跑一次搜索，返回原始结果

## 工作原理

Anthropic 的 `web_search_20250305` 是**服务端工具**，由 API 提供方在自家服务器跑搜索。中转站 / 兼容服务通常不支持，模型即使想搜索也拿不到结果，会回「搜索没有返回结果」。

启用本地搜索后，desktop 在本机拦截 web_search 调用，用选定的 provider 跑搜索、把结果直接合成为标准格式喂给模型，**任何 API 后端都生效**。
