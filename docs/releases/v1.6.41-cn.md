# Claude Desktop CN v1.6.41

在 v1.6.40 本地搜索的基础上新增第 5 种 provider：**「使用中转站搜索」**。

## 主要更新

### 新 provider：复用中转站已配置的搜索能力

如果你的中转站后端已开启 Brave 或 Tavily web search emulation（`gateway_websearch_emulation.go`），desktop 现在可以直接复用，**用户零额外配置**。

#### 工作原理

```
模型决定调用 web_search_20250305
        ↓
desktop bridge-server 拦截
        ↓
POST <CUSTOM_BASE_URL>/v1/messages
Headers: x-api-key: <CUSTOM_API_KEY>
Body: {
  "messages": [{"role":"user","content":"<query>"}],
  "tools": [{"type":"web_search_20250305","name":"web_search","max_uses":1}],
  "stream": false
}
        ↓
中转站看到「只有 1 个 web_search 工具」→ 触发 emulation
        ↓
中转站调 Brave / Tavily → 返回 web_search_tool_result blocks
        ↓
desktop 解析响应里的 content blocks → 合成给 Claude Code 引擎
```

中转站**完全不用改**，已有的 `isOnlyWebSearchToolInBody` gate 就能正好被这个最小请求触发。

### UX 设计

- 设置 → 联网搜索新增「使用中转站搜索」选项，**默认推荐位置**（排在 DuckDuckGo 之前）
- 选中后自动从 `CUSTOM_BASE_URL` / `CUSTOM_API_KEY`（localStorage 里你当前用的中转站凭据）同步到 bridge-server，无需重新输入
- 显示当前会用哪个中转站的 base URL
- 自动检测两种"不就绪"状态：
  - 用户在「官方 Anthropic API」模式（没有中转站）→ 提示切换模式
  - 用户没填 API Key → 提示先去「API 配置」补上
- 提供「重新同步当前中转站凭据」按钮，便于在 API 配置变更后刷新

### Provider 优先级（v1.6.41 起）

按推荐顺序：

| 顺序 | Provider | 何时用 |
|---|---|---|
| 1 | **中转站搜索**（新） | 中转站已开 Brave/Tavily 时，**零配置最优解** |
| 2 | DuckDuckGo | 不想用中转站、希望完全本地 |
| 3 | Tavily | 想要 LLM-optimized 搜索 + 总结，且愿意自己注册 |
| 4 | Brave | Tavily 不可用时的备选 |
| 5 | 不启用 | 上游 API 自己支持（如真 Anthropic API）|

### 隐私

中转站搜索的查询会经过你的中转站后端 —— 跟你正常聊天的链路一样，没有新增数据出口。如果想完全不经过任何第三方，选 DuckDuckGo 即可（连 DDG 都不会知道你在用 Claude）。
